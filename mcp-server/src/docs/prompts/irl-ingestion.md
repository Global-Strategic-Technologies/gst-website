# gst_irl_ingestion — prompt companion

> **Audience**: anyone modifying `mcp-server/src/prompts/irl-ingestion.ts` or debugging a live ingestion run.
> **Status**: maintained — update alongside every prompt version bump (version field in the module; history in the conventional-commit log, whose release messages pair prompt + server semver).
> **Provenance**: distilled from the two archived BL-045 documents — `MCP_SERVER_FILLED_IRL_INGESTION_BL-045.md` (design doc, frozen at v0.1.0-era scope) and its `TOOL_SCHEMA_ENFORCEMENT_SPEC` (the server-0.4.0 `_audit` pivot). The prompt has evolved far past both (currently **v0.22.4**); where this doc and the frozen docs conflict, the shipped code wins and this doc reflects the code.

## What it does

`gst_irl_ingestion` is the bookend to `gst_information_request_list`: the partner sent the universal intake checklist, the target returned it filled, and this prompt ingests the populated IRL and drives every applicable Hub tool surface in one turn — extracting the 13 diligence dimensions, invoking up to 10 orchestrated tools through per-tool inclusion gates, and synthesizing the outputs into a single partner-level dossier with sections (A)–(K), each tool-backed section closing with a state-carrying Hub deeplink. It is scenario-neutral (buy-side, sell-side, value-creation, post-close); `transactionContext` modulates voice only, never tool selection. Two library embeds ride along: the decoupled IRL generator source (`gst://irl/source`, the canonical section taxonomy for reconciling minimally-formatted replies) and `gst://library/vdr-structure` (verbatim VDR folder labels for follow-up requests).

## Execution model

**Three body shapes**, dispatched in `build()`: no `filledIrl` → interactive paste-request; `filledIrl` + `mode: full` → one-shot sweep; `filledIrl` + `mode: extract-only` → extraction-only.

**Workbook column contract (BL-120, all bodies)**: the IRL xlsx has seven columns — `A Reference | B Request | C Status | D File Location | E Comments | F Notes | G Response` — and D/E/F carry authored content, not metadata (GST pre-populates research into Comments, sources into File Location, caveats into Notes; the recipient confirms via Status). Each filled row renders as `- <ref> <request> [<STATUS>] — <answer> (Source: <D>) (Note: <F>)`, where `<answer>` is **G and E joined into one contiguous unlabelled span** — a label between them breaks citations that read across the boundary. Source and Note stay **outside** the answer slot, so a row carrying only a filename renders `— <NO RESPONSE> (Source: …)` and cannot open a gate. The contract also warns the model to trust the data sheet's header row rather than the Instructions sheet (workbooks in the wild document a stale five-column layout), and states the citation-hygiene rule: cite from the answer slot only, never from `(Source:)` / `(Note:)` — both are inside the verifier's haystack, so a filename citation verifies and raises no gap. Rationale and the accepted residual: [ADR-0015](../../../../src/docs/adr/0015-irl-canonical-body-reads-full-workbook.md). The operator-side `npm run irl:extract` emits this same shape.

**Fill-ratio pre-flight (blocking, before any extraction)**: walk the 10 canonical IRL sections (00–09; optional 10/11 excluded), compute `fillRatio = substantiveCells / totalResponseCells` over the **composed answer span** (Response + Comments — see the column contract below), composing before counting. `< 15%` → HALT with a wrong-IRL warning, emit only (A). `15–40%` → proceed with partial-IRL framing and tightened elision (any tool whose source sections are all empty is skipped, surfaced in (J)). `≥ 40%` → proceed normally. The ratio is the first sentence of (A) in all paths.

**Inclusion gates** (evaluated per tool; failures are elided with a (J) entry, `forceTools` overrides): `generate_diligence_agenda`, `assess_infrastructure_cost_governance`, and `search_radar` always pass; `compute_techpar` requires ARR (Section 00) AND an eng-cost or hosting signal (02/03); `estimate_tech_debt_cost` requires ≥ 1 Section 04 row with a substantive answer (a file pointer or a caveat is not signal); `search_regulations` requires a Section 09 framework OR a fired EU-AI-Act / NIS2 conditional trigger; `search_portfolio` requires a Section 00/01 product-or-industry signal; the two facet tools inherit from their search siblings.

**Meta JSON fence** — the first content of every dossier, in both modes: `promptName`, `promptVersion` (server-overridden from the prompt registry), `modelVersion`, `mode`, `verbosity`, `transactionContext`, `fixtureFillRatio` + `fixtureFillRatioStatus` (`ok`/`partial`/`halt`), `gatesPassed`, `gatesElided` (`{tool, reason}`), `conditionalTriggersFired` (`EU_AI_ACT`/`NIS2` only), `forceToolsApplied`. In full+verbose it is transcribed verbatim from `compose_dossier_envelope` output rather than model-authored.

**Output sections**: meta fence → **(A)** target snapshot → **(B)** diligence agenda → **(C)** TechPar → **(D)** ICG → **(E)** tech debt → **(F)** regulatory exposure (one subsection + one deeplink per framework) → **(G)** comparable engagements → **(H)** market signal → **(I)** synthesis/handoff memo → **(J)** gap list (always emitted; six model-supplied categories plus server-appended `provenance-gap`/`tier-mismatch`/`tier-fabrication`/`map-absent`) → **(K)** provenance footer (verbose only; one line per load-bearing claim → IRL anchor + tier). Verbose full mode also emits an `audit: <letter>` JSON fence + self-check after each of (C)–(H), and a mid-sweep tool-error degradation rule (verbatim error, section marked extraction-only, sweep continues; halt only if the agenda prerequisite fails).

**Envelope chain (full + verbose)**: converge citations on `validate_irl_provenance` first (BL-051 — cheap iteration until ≥ 0.90 verified or 4 rounds; BL-053 array-form citations for multi-bullet claims), then call `compose_dossier_envelope` ONCE; it returns the meta fence, (J), and (K) as literal markdown. The IRL body travels by hash, not bytes: one-shot mode pre-populates the server body cache at prompt-render time (BL-079) and embeds a `**Body-binding hash:**` directive the model copies as `irlBodyHash` (`irlSource: partner-paste-verbatim-prepop`); interactive mode routes through `prepare_irl_body` (BL-076, `Bl076BodyCacheMissError` on skip).

**Extract-only** runs the same pre-flight, gates, and `_audit` discipline but invokes nothing: it emits a `worksheet: generate_diligence_agenda` fence, one `payload: <tool>` fence per gate-passing tool, `elided: <tool>` fences for failures, and (J) — no dossier prose, no deeplinks, no envelope.

## Server-side enforcement

The frozen design doc's original theory was body-level coaching. It failed empirically: three body-rewrite rounds (v2/v3/v4) against a real client IRL (SanFran, June 2026) showed the model treats body directives as descriptive context, not procedure — currency, headcount-scope, dataSensitivity, and MTTR-OPEN clauses were all skipped. The `TOOL_SCHEMA_ENFORCEMENT_SPEC` (shipped at server 0.4.0) pivoted enforcement to the tool seam: a required `_audit` sibling on each tool's input schema, with cross-field refinements run in the handler body (plain `ZodObject` only — the MCP SDK publishes an empty schema for unions/`ZodEffects`) that reject with a structured BL-045 diagnostic the model retries against. Per-tool families, as implemented in `mcp-server/src/schemas/`:

- **`diligence-audit.ts`** (`generate_diligence_agenda`): per-dimension `tier` (`1`/`2`/`3`) + `citation` matching `Section NN — <substantial excerpt>`; tier↔value coupling (tier 3 ⇔ `unknown`, both directions rejected otherwise); `revenueRange` currency normalization (`nativeCurrency` enum + `currencyConversion {nativeAmountMillions, usdRate, convertedUsdMillions}` with bracket cross-check); `headcount.scope` must be `engineering-only` for non-unknown values; `dataSensitivity.piiCategoriesPresent` bucket cross-check (e.g., `low` incompatible with PHI/PCI); `growthStage.velocityEvidence` enum.
- **`techpar-audit.ts`** (`compute_techpar`): single declared `monetaryBasis` (currency + conversionRate) across all money fields, plus per-monetary-field `annualizationSource` (`irl-annualized-stated` | `monthly-x12` | `ytd-annualized-with-period` — requires `ytdMonths` 1–11 + a `ytdMathCheck` arithmetic-consistency block | `estimated-from-headcount` | `estimated-from-anchor`). This closed the observed cross-run swings (9.1%/13.9%/31.2% R&D% on the same fixture from ad-hoc annualization).
- **`tech-debt-audit.ts`** (`estimate_tech_debt_cost`): `mttrSource`/`incidentsSource` enums (`irl-stated` | `irl-open` | `irl-absent` | `irl-scope-mismatch`); any non-`irl-stated` source REQUIRES the value be `null` (placeholder substitution structurally impossible); nulled fields are elided from the engine and returned in `extractionOnly: [...]`, which the dossier renders as extraction-only with a (J) follow-up.

Two later enforcement layers extend the same pattern at the envelope seam: **derived-tier discipline** — `deriveTier()` computes effective tier from citation properties (verbatim substring → tier 1; `Section --` sentinel → partner-supplied; neither → `tier-fabrication` gap), so model-declared tier is a hint, not authority (closes the v11 tier-demotion gaming pattern; see [ADR-0003](../../../../src/docs/adr/0003-irl-xlsx-canonicalization-hash-bind.md)) — and **body-by-hash** — the IRL body is server-cached and re-hydrated by `irlBodyHash` with a sha256 bind check, never round-tripping through model emission (see [ADR-0002](../../../../src/docs/adr/0002-irl-body-by-hash-cache.md)). BL-063 additionally enforces `defaultFiredFrameworks` at the schema seam: partition vs. `conditionalTriggers.fired`, certification-scope rejection, and Hub-backing auto-degrade to `map-absent:` gaps.

## Provenance & audit surface

Every body shape mandates a closing **`BL-045-VERIFY`** fenced YAML block — the operator's single-surface run audit. At v0.21.x it carries: `promptVersion`; `runScenario`; `filledIrl` (bytes / `source` enum including `partner-paste-verbatim-prepop` and an honest `placeholder` option / 120-char head+tail fingerprints); `firstEnvelopeCall` (`irlBodyHash`, `hashBindResult`, `provenanceVerification` counts incl. `tierMismatches`/`tierFabrications`); `precheck` (iterations / attemptsTotal / outcome / errorsEncountered); `countersScope` + `toolCallCounts` — both copied VERBATIM from the envelope output (BL-071 + BL-121; `attempted = succeeded + rejected + errored` within a snapshot, with precheck fields derived by identity from the `validate_irl_provenance` row — model self-narration demonstrably drifted, so the server counts are ground truth). **`countersScope` states how far back the snapshot reaches** and therefore whether the derivation identities are checkable at all: `session` (stdio — one process, one counter map, whole session), `run` (remote + the durable run-scoped store read successfully — every call against this IRL body, across requests), `request` (remote with no readable store — only the envelope call's own request; earlier calls are legitimately absent and the model is told to leave the gap visible rather than close it). The identities are stated conditionally on that value, and `attemptsTotal === attempted` is replaced by a reconciliation subtracting the transport-classed `errorsEncountered` entries — durable writes land at wrapper exit, so an attempt that never reached the server was never countable; `toolErrors` (per-attempt diagnostics, strict partition from precheck errors, arithmetic-checked against the counts); envelope-call cumulatives + `meaningfulRecallsHaveDifferentInputs`; `conditionalTriggers` (considered/fired/suppressedWithRationale/defaultFiredFrameworks); structured `gatesElided`; and `response` (continuations, verify-block emission point, `compactionEvents` with null-preferred-over-false-zero semantics).

`hashBindResult` semantics are load-bearing: **`pass-bound`** means the hash was copied from a server-emitted `**Body-binding hash:**` directive (one-shot mode — the bind is to partner-authoritative bytes; high audit grade); **`pass-internal`** means no directive existed (interactive mode) and the model self-computed the hash — honest internal consistency only, medium audit grade. Reporting `pass-bound` without a directive to copy from is a fabricated audit claim.
